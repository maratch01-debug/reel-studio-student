# Reel Studio

This folder is the student's local production project. Read START.txt, SETUP.txt and TOOLS.txt on first use. The student talks to the coding agent, which runs the tools locally. Prefer the bundled Reel Studio MCP when the session exposes it. The same pipeline is available through the local CLI.

If the student provides the installation prompt or asks to set up this project, use the open repository at https://github.com/maratch01-debug/reel-studio-student. Reuse the current clone if it is already open. For the installation prompt with demos, run the OS installer with its demo flag and verify the generated files. If the student asks for a reel on a topic, install any missing base dependencies and go straight to that reel.

1. Treat a request like “Сделай рилс с тигрицей про прокат настольных игр” as a production request. Write a brief JSON in this checkout and call reel_studio_produce or run studio.py produce. See TOOLS.txt and examples/student-demo.json for the format. Continue through export and verification in the current chat. Return the finished MP4 first, then the editable project. Open a preview only if the student requests one.
2. Present the three student formats in this order: classic (the talking head), comic, talk (the character acting inside a scene). Default to classic for an ordinary reel request. Follow the student's chosen format when specified. For classic, read CLASSIC.md and examples/classic-demo.json. Start with three separate cuts: a large head and frame, a numeric contrast, then the surprising object. Give every later idea its own illustration or infographic. End on a relevant payoff and action. Use the student's head, voice and CTA. For the classic soundtrack use music: "classic" unless the student supplies a track.
3. For classic and comic use the requested bundled character or a folder with matching transparent idle.png, mouth-small.png and mouth-open.png. Inspect alignment and reuse matching poses in future episodes. For talk use the same character reference across full-scene keyframes. Give each scene one clear gesture or action and visible environmental motion, such as falling drops, moving tools, or a drifting object. Use the scene narration as LTX audio input and keep framing stable enough to read the action. Replaceable student inputs include character, narration, and music.
4. Open with a specific shot and a spoken hook in the first two seconds. Give each scene one new idea and a change the viewer can see. End on a concrete payoff or action. Read the script aloud and cut phrases that sound written. Use supplied or verified figures or clearly labeled examples. Break captions into short spoken phrases and align them to the actual recording. Use supplied artwork or local Flux.2 Klein 4B when available. Keep optional services on loopback.
5. Check the base tools in SETUP.txt. Use the student's WAV or named profile when provided. Use the bundled voice for the requested character when no other voice is specified. Audition a short hook internally if needed, then continue with the current voice. Offer voice samples when the student asks to compare voices. Check pronunciation and delivery before animating. Remotion assembles the visuals, FFmpeg masters the mix. Use one or two sound accents for a reveal or a number. Review the master with sound.
6. For several topics, write one reels array with distinct IDs and run produce once. Render sequentially and keep completed outputs and cached files. Verify the runtimes, framing, captions and presence of sound before returning links. For a technical check use reel_studio_verify.
7. Use private assets and outputs only in the student's own workspace. Reels are rendered locally. Publishing or sharing is a separate user request.
8. If the student uses the MCP setup, run reel_studio_doctor in a new session opened from the repository root. If MCP is unavailable in the current session, run the local CLI and finish the requested reel in that session. See MCP.md.
